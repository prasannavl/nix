# tuicr on pvl-a1, pvl-l5, and pvl-x2

On 2026-09-26, the three PVL desktop/primary hosts gained
[`agavra/tuicr`](https://github.com/agavra/tuicr), a code-review TUI with vim
keybindings for reviewing AI-generated diffs.

## Package unit

`lib/ext/tuicr/` builds the pinned GitHub source with
`rustPlatform.buildRustPackage`. `lib/overlays/default.nix` exposes `pkgs.tuicr`
to `environment.systemPackages` on `pvl-a1`, `pvl-l5`, and `pvl-x2`.

The upstream suite uses `git` to create throwaway repositories. Since 0.30.0, it
also uses `ps -o stat= -p PID` to check that a clipboard timeout kills the
shell's children. Declare `git` and `unixtools.ps` in `nativeCheckInputs`;
otherwise the process-status check fails with `ENOENT` in the Nix sandbox.

The binary dynamically links only `libgcc_s`, `libm`, and glibc. Clipboard
support uses `arboard` with the Wayland data-control path, so it needs no
external `wl-clipboard`/`xclip` binaries.

## Updates

`lib/ext/tuicr/update.sh` reports and updates the version, revision, source
hash, and `cargoHash`, and participates in `scripts/update.sh` as the `tuicr`
`lib/ext` unit:

```console
scripts/update.sh --report --only-ext-tuicr
scripts/update.sh --only-ext-tuicr
lib/ext/tuicr/update.sh --report
lib/ext/tuicr/update.sh --force
```

`cargoHash` is derived by building a staged copy of the unit with a placeholder
hash against the repository's own nixpkgs (through the shared
`ab/repo/self-flake.nix` helper) and reading the reported hash. This verifies
vendoring, not the package tests.

## Boundaries

Only the CLI is installed. The bundled agent skill (`skills/tuicr/SKILL.md`) and
any export-target credentials (GitHub/GitLab/etc.) stay user-owned; `tuicr`
reads them from the user's environment and config.

## Validation

```console
nix build .#nixosConfigurations.pvl-a1.pkgs.tuicr --no-link --print-out-paths
```

Build the package alone after a pin update to run the upstream suite before a
fleet build.
