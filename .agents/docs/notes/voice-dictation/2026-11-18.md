# Voice dictation integration (2026-11-18)

Scope: shared `pvl` Home Manager profile on Niri, Sway and GNOME Wayland.

- Pin upstream Voxtype, whisrs and Vocalinux flakes; share the existing
  `unstable` nixpkgs input to avoid redundant package-set locks.
- Keep upstream packages/build logic rather than vendoring three applications.
- Default Vulkan for Whisper on AMD/NVIDIA. Expose CPU, whisrs CUDA/HIP, Voxtype
  Whisper ROCm and Voxtype ONNX CUDA/MIGraphX as opt-in builds.
- Provide Voxtype ONNX CPU in parallel with Whisper/Vulkan using a separate
  `voxtype-onnx` command, avoiding two `bin/voxtype` in one profile.
- Enable `hardware.uinput` for Wayland injection, add `pvl` only to the `uinput`
  group, do not grant the broad `input` group.
- Do not enable three concurrent autostarting microphone daemons or assign
  competing desktop hotkeys; users explicitly select a tool.
- Do not claim model/runtime combinations that upstream's Nix packages omit:
  Vocalinux Parakeet extra is absent; Voxtype ONNX has no Vulkan and its
  MIGraphX build has Parakeet acceleration only; whisrs needs a sidecar for
  Parakeet/Cohere.
- whisrs supports phrase-level local Whisper streaming and OpenAI-compatible
  ASR/TTS servers. Ship no unrequested cloud credentials or TTS daemon.

First-use and model/backend matrix: `users/pvl/voice/README.md`. Verification
and any unresolved build issues are recorded in that README or in the final
handoff; no host activation is part of this change.

## whisrs Vulkan was never enabled (correction)

Reported symptom on `pvl-a1`: `whisrsd` printed `use gpu    = 0`, `devices = 1`,
`backends = 1`, and loaded the model as `CPU total size`, although the installed
binary came from `whisrs-vulkan-0.2.1`. That store path was built from the
derivation the overlay produced, so the package name was not evidence.

Root cause: `lib/ext/whisrs/default.nix` set the backend with
`upstream.overrideAttrs (old: { buildFeatures = ...; })`. `buildFeatures` is an
**argument** of `rustPlatform.buildRustPackage`, not a derivation attribute:
nixpkgs copies it into the derivation's `cargoBuildFeatures` variable
(`pkgs/build-support/rust/build-rust-package/default.nix`), and
`cargo-build-hook.sh`/`cargo-check-hook.sh` read that variable. `overrideAttrs`
cannot reach the function argument, so the derivation ended up with

- `buildFeatures = "vulkan"` — an env var no hook reads, and
- `cargoBuildFeatures = ""` — the one that matters,

and `cargo build` ran without `--features vulkan` while still succeeding. The
old binary had zero `ggml_vk*` symbols and no `libvulkan.so.1` in `DT_NEEDED`.

whisper-rs makes this failure silent: `WhisperContextParameters::default()` uses
`use_gpu: cfg!(feature = "_gpu")`, so a CPU build reports `use gpu = 0` instead
of attempting the GPU, and whisper.cpp registers only its CPU backend. Nothing
errors; transcribes on the CPU.

Fix in `lib/ext/whisrs/default.nix`:

- Set `cargoBuildFeatures = [backend]` and `cargoCheckFeatures = [backend]` in
  `overrideAttrs`, i.e. the variables the cargo hooks consume, and comment why
  `buildFeatures` there is inert.
- Add a `postInstall` gate on the Vulkan variant: `readelf -d $out/bin/whisrsd`
  must contain `libvulkan.so.1`. A CPU-only build links and starts normally, so
  the build succeeding cannot be the gate. (`alejandra --check` passes.)

Qualification:

- `nix build` of `pkgs.voiceTools.whisrs.vulkan` on `pvl-l5` succeeded, twice:
  once with the feature fix, then again with the `postInstall` gate added.
  Output `/nix/store/1pvvdcfbqk42dyk1di44g8rg25pizcqm-whisrs-vulkan-0.2.1`
  contains 194 `ggml_vk*` symbols, exports `ggml_backend_vk_reg`, and has
  `NEEDED libvulkan.so.1` resolving to the Nix `vulkan-loader`.
- The gate is discriminating, not decorative:
  `readelf -d .../bin/whisrsd |
  grep -c libvulkan` returns 1 for the fixed
  output and 0 for the pre-fix `5d78waf4...-whisrs-vulkan-0.2.1`, so the old
  CPU-only build would now fail the install instead of shipping.
- That output, run on `pvl-a1` against the existing
  `~/.local/share/whisrs/models/ggml-small.en.bin`, printed
  `whisper_init_with_params_no_state: use gpu    = 1`,
  `ggml_vulkan: Found 2 Vulkan devices:` (`NVIDIA GeForce RTX 4060 Laptop GPU`,
  `AMD Radeon 890M Graphics (RADV STRIX1)`), `devices = 3`, `backends = 2`, and
  `whisper_model_load: Vulkan0 total size = 487.00 MB`. The Vulkan ICDs on
  `pvl-a1` (`/run/opengl-driver/share/vulkan/icd.d`) were already complete;
  nothing runtime-side was missing.
- Not done: no host activation. `pvl-a1`'s own `~/src/nix` checkout is behind
  and does not carry this patch, so its profile still installs the CPU-only
  build until the change is synced and the profile rebuilt. No GPU transcription
  latency measurement was taken.
- The earlier claim in this note — "Inspected whisrs Nix derivations:
  `buildFeatures=vulkan` plus Vulkan SDK variables" — is wrong as a
  qualification: that env var is not what the build hooks read. Likewise the
  `voxtype`/`vocalinux` Vulkan variants were not re-qualified by this change;
  they take backend-enabled packages from upstream rather than patching
  features, but only `voxtype`'s GGUF worker has an ELF `libvulkan.so.1` gate.

## Backend audit: argument-only derivation attributes

Follow-up sweep of every `overrideAttrs` call in the tracked `*.nix` files (71
sites) for the same class of defect as the whisrs one: an attribute that exists
only as an _argument_ of a derived builder and therefore never reaches the
derivation.

In this nixpkgs, `rustPlatform.buildRustPackage` is built with
`lib.extendMkDerivation`, whose `overrideAttrs` overrides the attributes handed
to `mkDerivation` — that is, the output of `extendDrvArgs`, after the builder
arguments have been mapped. Consequences:

- Argument names that `extendDrvArgs` re-exports as variables keep working
  through `overrideAttrs`: `cargoBuildFeatures`, `cargoCheckFeatures`,
  `cargoBuildType`, `cargoDeps`, `buildAndTestSubdir`, `doCheck`, `patches`.
- Argument names that are consumed at eval time only are dead as overrideAttrs
  attributes: `buildFeatures`, `checkFeatures`, `buildNoDefaultFeatures`,
  `cargoLock`, `cargoVendorDir`, `cargoPatches`, `cargoRoot`, `logLevel`,
  `useNextest`, `auditable`, `depsExtraArgs`, `cargoUpdateHook`. `RUSTFLAGS` is
  additionally dropped by `excludeDrvArgNames`; it must go in `env`.

Findings:

- `lib/ext/whisrs/default.nix` was the only real hit (`buildFeatures`) and is
  fixed. nixpkgs itself writes `cargoBuildFeatures = [ ... ]` where it needs to
  add a feature from outside the package definition (`rustdesk-flutter`), which
  is the same level this overlay now targets.
- `overlays/niri.nix` overrides `cargoDeps`, which is a real derivation
  attribute (`cargoDeps = ...` inside `extendDrvArgs`), so it takes effect.
- The `cargoVendorDir` / `cargoLock` hits in `lib/flake/rust/tests/*` and
  `lib/flake/tests/pvl/*` are fixtures against this repo's own builder, which
  consumes those names itself; they are also used deliberately as "tamper this
  input" cases for the recipe checks. No change.
- No Python, Emacs or other derived-builder package in this repo is overridden
  through `overrideAttrs` with an argument-only name.

## Design simplification: features compose (correction)

Supersedes the SONAME gates and the named-variant matrix above.

- Cargo features are additive, so a backend needs no derivation family of its
  own: `voice.whisrs.mk ["vulkan" "cuda"]` is one daemon that can use either GPU
  and `mk []` is the CPU build. `accel` is only a host-facing name for those
  feature lists.
- Voxtype composes upstream's own builds instead of restating feature lists:
  `mk {whisper; onnx}` extends a Whisper build with the engine list, inputs,
  `ORT_LIB_LOCATION` and runtime wrapper read from `voxtype-onnx-unwrapped`.
  Upstream keeps owning its lists; this repo owns only the composition.
- The `DT_NEEDED` gates are gone. They checked a proxy (`readelf` shows linkage,
  not GPU use), needed a per-backend soname that was itself unqualified
  (`libcublas` is direct, HIP's direct entries are `libhipblas`/`librocblas` and
  `libamdhip64` may arrive transitively, and a `dlopen`ed backend has no entry
  at all), and duplicated shell into every GPU derivation; the GGUF worker's
  `objdump` gate and its `binutils` input went with them. Model-load output
  stays the runtime check.
- No features helper file: each `mk` adds `cargoBuildFeatures`/
  `cargoCheckFeatures` (the env vars the nixpkgs cargo hooks read) in the
  `overrideAttrs` it already builds, with the contract written down beside it. A
  shared four-line helper was tried and inlined: two call sites did not justify
  the extra file, import and nesting, which also hid which attributes merge. An
  evaluation-time assertion was drafted and dropped: with the helper writing the
  env var itself, the assertion only re-reads its own value, so it cannot catch
  the historical `buildFeatures` mistake (verified by evaluating a derivation
  built that way). The comment and the model-load check are the guards.
- `pkgs.sqlite` dropped: `rusqlite` is bundled and upstream builds without it.
  Oniguruma stays, taken from upstream's ONNX inputs plus one entry.
- One `voxtype` command now carries Whisper/Vulkan and the ONNX engines, so the
  separate `voxtype-onnx*` wrappers and their naming shim are gone. `accel.cuda`
  is Vulkan Whisper plus the CUDA ONNX provider, since upstream ships no Whisper
  CUDA build.
- Evaluated for `pvl-a1`, `pvl-l5`, `pvl-x2`: each profile gets
  `voxtype-vulkan-with-gguf-worker` (cargo features `gpu-vulkan` plus all seven
  ONNX engine features, `ORT_LIB_LOCATION` set, oniguruma in the graph) and
  `whisrs-vulkan-0.2.1`; `whisrs.mk ["vulkan" "cuda"]` evaluates to
  `whisrs-vulkan-cuda-0.2.1` with both feature sets and both input sets.
- Still **unbuilt**: the combined `whisper=vulkan` + ONNX binary (upstream ships
  those as two artifacts to keep each small), `whisrs.cuda`, `whisrs.rocm`,
  `voxtype.rocm` and the ONNX CUDA/MIGraphX builds. Their first build is the
  qualification before a host moves off Vulkan.
