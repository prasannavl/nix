## Cause and correction

manager8 tree_nar verifies canonical NAR bytes but creates new copied files
without normalizing modification times. NAR equality excludes timestamps.
Consequently the isolated vendor copy presents fresh input mtimes against epoch1
restored build-script outputs. Cargo's actual strict-newer RerunIfChanged
comparison therefore rejects freshness for the inspected upstream units;
matching JSON fingerprints and proper artifact wiring cannot override it. This
establishes a concrete local freshness rejection, not that every one of the200
external compilation events has a separately traced first cause.

The correction sets canonical Nix epoch1 timestamps only on newly created
destination regular file FDs, destination directory FDs after children, and
nofollow symlinks. Source metadata/content, original
stat9/name/owner/NAR/custody gates and all package recipes remain unchanged. The
public Nix2.32.2 canonical metadata
[implementation](https://raw.githubusercontent.com/NixOS/nix/2.32.2/src/libstore/posix-fs-canonicalise.cc)
also specifies mtimeStore1. This corrects qualification transport semantics; it
does not change the build-system strategy to hide work.

Warm original97rg --rebuild/mpnp-version runtime qualification must consume the
corrected Source after fresh reviews/admission/NAR/reference/custody. Cargo
reuse remains unqualified until actual build observations pass. No native warm
run, recipe instrumentation, Git publication or adoption occurred in these two
units. Manager8 is frozen and must not be edited or rearmed.
